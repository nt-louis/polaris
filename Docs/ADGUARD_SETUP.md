# AdGuard Home Setup & Architecture Guide

This document outlines the deployment and configuration of the Global DNS Ad-Blocking infrastructure for the Net-Stream project.

## Architecture Overview

The AdGuard Home service is deployed within a dedicated **Network Gateway** stack.

*   **Gluetun (VPN)**: All traffic is isolated via a VPN tunnel.
*   **Tailscale**: Provides a secure, private network identity (`dns-gateway`) and stable IP.
*   **AdGuard Home**: Acts as the forwarding DNS resolver and filtering layer for the Tailnet. Configure recursive upstream infrastructure separately if true recursion is required.
*   **Caddy**: Provides a reverse proxy for the web dashboard and DNS-over-HTTPS (DoH) endpoint.

---

## 1. Initial Deployment

1.  Navigate to the `Network/` directory.
2.  Add the variables documented in `Network/.env.example` to the
    `network_exit_node` config in the active VPS Doppler project.
3.  Verify Doppler access and deploy from the repository root:
    ```bash
    cd ~/polaris
    ./manage.py secrets verify
    ./manage.py deploy --vps A
    ```

Do not create a production `Network/.env` or start this stack with direct
`docker compose` commands. The manager injects the config through Doppler (with
transparent fallback to offline SOPS snapshots).

---

## 2. AdGuard Home Wizard Setup

Access the setup wizard at `http://dns-gateway:3000` (via Tailscale) or your public domain.

1.  **Admin Web Interface**: Set the port to **3000**. (Port 80 is reserved for Caddy).
2.  **DNS Server**: Set the port to **53**.
3.  **Static IP**: Click Next (Tailscale provides a stable IP).

---

## 3. DNS Configuration

In the AdGuard Home Dashboard (**Settings -> DNS settings**):

### Upstream DNS Servers (Encrypted)
Use a mix of providers for high availability:
```text
https://cloudflare-dns.com/dns-query
https://dns.google/dns-query
https://dns.mullvad.net/dns-query
https://dns10.quad9.net/dns-query
```

### Bootstrap & Fallback DNS (IPv4 ONLY)
> [!IMPORTANT]
> **DO NOT use IPv6 addresses (with colons) in these sections.** 
> Most VPN tunnels (Gluetun) do not support IPv6 routing. Including IPv6 bootstrap IPs will cause massive 10-20 second timeouts on every DNS query.

Use standard IPv4 addresses for reliability:
```text
1.1.1.1
8.8.8.8
9.9.9.9
```

## 4. Global Tailscale Integration

To enable network-wide ad-blocking:

1.  **Find your IP**: In your terminal, run `docker exec network-gateway-tailscale tailscale ip -4`. This is your `dns-gateway` IP.
2.  Go to the [Tailscale Admin DNS Console](https://login.tailscale.com/admin/dns).
3.  Add a **Custom Nameserver**: Use the IP from step 1.
4.  Enable **"Override local DNS"**.
5.  Enable **"Use with exit node"** to maintain protection while on VPN.

## 5. DNS-over-HTTPS (DoH) for Mobile Devices

To use AdGuard outside of Tailscale (e.g., on mobile devices):

### Internal AdGuard Configuration
The compose file mounts the host Caddy certificate directory at
`/opt/adguardhome/certs`. The AdGuard state file is persistent and must be
configured in the AdGuard UI or `Network/state/adguard/conf/AdGuardHome.yaml`:

1. **Enable Encryption** in **Settings -> Encryption**.
2. Set the HTTPS port to **3443**. The internal Caddyfile proxies the public
   `/dns-query` path to this port.
3. Point AdGuard's certificate and private-key paths at the files under
   `/opt/adguardhome/certs` that match `ADGUARD_DOMAIN`.
4. Set `allow_unencrypted_doh: true` only if clients will use the separate
   Tailscale-only Caddy route, which forwards `/dns-query` to AdGuard's plain
   DNS listener on port `3000`. Do not enable this setting without restricting
   access to the trusted Tailnet.

The certificate mount is supplied by host Caddy's ACME storage. The directory
must exist before the AdGuard container starts; certificate issuance and host
Caddy configuration are prerequisites, not generated by this compose stack.

### Internal Caddy Bridge (`Network/Caddyfile`)
The internal Caddy must route public `/dns-query` traffic to the encryption port:
```caddy
:80 {
    # Dashboard
    handle_path /adguard/* {
        reverse_proxy 127.0.0.1:3000
    }
    
    # DoH Bridge
    handle /dns-query* {
        reverse_proxy https://127.0.0.1:3443 {
            header_up Host your-domain.com
            transport http {
                tls_insecure_skip_verify
                tls_server_name your-domain.com
            }
        }
    }
}
```

### Host Caddy Configuration (VPS Bare Metal)
Your VPS host Caddy serves over plain HTTP (since TLS is terminated upstream at Cloudflare) and proxies to the internal gateway using Tailnet FQDN:
```caddy
http://adguard.your-domain.com {
    import base_security
    reverse_proxy dns-gateway.<tailnet-domain>.ts.net:80 {
        import proxy_settings
    }
}
```

### URL Endpoint
The public DoH endpoint is:
**`https://adguard.your-domain.com/dns-query`**

### Usage
*   **Android**: Set "Private DNS" to `adguard.your-domain.com`.
*   **iOS**: Generate a DNS profile pointing to the DoH URL.
*   **Browsers**: Set "Secure DNS" to the DoH URL.

## 6. Maintenance & Troubleshooting

*   **Logs**: `docker logs network-gateway-adguard`
*   **Redeploy**: Always use `./manage.py redeploy` after modifying the `Caddyfile` or `docker-compose.yml`.
*   **Query Log**: Use the AdGuard Home "Query Log" tab to debug blocked domains or see client activity.
